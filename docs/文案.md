# PLogin 文案与玩家提示汇总

> 适用于 Minecraft 26.2 / Fabric Loader 0.19.5 / Java 25。
> 实际聊天消息前缀统一为 `[PLogin]`，对话框文字不带前缀；踢出/标题消息按代码中的颜色显示。
> 本文件同时包含：对外宣传文案、玩家提示、服主公告模板、命令说明、配置语义。

---

## 1. 对外宣传文案

### 1.1 一句话版

**PLogin：让正版和离线玩家在同一个 26.2 Fabric 服务器里共存。**

### 1.2 短版（服务器列表 / 群公告）

```
PLogin —— 26.2 Fabric 混合登录
正版玩家直接进服，离线玩家在连接阶段用对话框注册 / 登录；
正版玩家可设置离线备份密码，正版验证不可用时用密码进入；
未登录玩家在配置阶段就被拦住，不会进入世界；
客户端不需要安装任何模组。
```

### 1.3 完整版

```
PLogin 是一个面向 Minecraft 26.2 Fabric 服务端的混合登录模组。

它把正版验证和离线认证放在同一套流程里：
- 正版玩家验证成功直接进入，保留正版 UUID、皮肤、披风；
- 离线玩家使用离线 UUID，在原版 Configuration 阶段看到注册/登录对话框，
  输入密码后才会继续加载世界；
- 正版玩家可以额外设置“离线备份密码”，
  在正版验证不可用或自己使用离线客户端时，用同一个名字和密码进入；
- 离线备份密码验证通过后，服务端清掉 dialog，并用原版 transfer 把连接转回正版 UUID/存档；
  正版同名在线时会拒绝这次备份登录，而不是踢人；
- 未登录玩家不会出现在 PlayerList/Tab/世界中，也不需要 limbo 维度、
  位置冻结、失明或数据包过滤；
- 客户端不需要安装 PLogin，只需要服务端有 Fabric API + PLogin。
```

### 1.4 特性列表

- ✅ `online-mode=true` 下混合登录
- ✅ 正版 UUID / 正版皮肤 / 披风 / 鞘翅保留
- ✅ 离线 UUID 修复（`OfflinePlayer:<name>`）
- ✅ 配置阶段对话框注册 / 登录 / 超时 / 退出按钮
- ✅ 正版玩家设置离线备份密码
- ✅ 备份密码通过后先清 dialog，再用原版 transfer 切换到正版 UUID/存档
- ✅ 断开前先清除 dialog，避免客户端卡在自定义屏幕
- ✅ 不再使用 limbo 维度，不冻结玩家、不拦截游戏数据包
- ✅ LittleSkin + MineSkin 离线皮肤（可选）
- ✅ 客户端零模组

### 2.7 系统消息规则

- 未完成认证时：玩家还在 Configuration 阶段，没有进入 PlayerList，不会广播 xxx joined the game；
- 认证完成、真正进入世界时：原版正常广播 xxx joined the game，Tab 正常显示；
- /logout 会断开连接，原版正常广播 xxx left the game；重连后重新走对话框；
- 不再需要隐藏/补发 joined/left 消息。

## 3. 命令文案

### 玩家命令

```
/register <密码> <确认密码>    仅正版玩家：设置/更新离线备份密码
/logout                        断开连接，重新连接后再次登录
/changepassword <旧> <新>      修改密码（离线账号或正版备份密码）

别名：/reg /cp
```

> 注册和登录已经移到连接阶段的对话框，不再提供 /login。

### 管理员命令

```
/plogin reload                         重载配置与语言
/plogin list                           已注册用户数
/plogin info <玩家>                    UUID / 类型 / 状态 / 最后登录
/plogin unregister <玩家>              删除登录记录（不删除世界存档）
/plogin resetpassword <玩家> <新密码>   重置离线密码
```

> /plogin unregister 只删除 users.json 里的登录记录，不删除正版 UUID 的
> playerdata / 世界存档；在线玩家重新连接后生效。

## 4. 服主公告模板

### 4.1 开服公告

```
【PLogin 混合登录】
- 正版玩家直接进服，无需注册；
- 离线玩家连接后会看到原版登录对话框：第一次设置密码注册，之后输入密码登录；
- 想设置离线备份密码的正版玩家，进服后执行 /register <密码> <确认密码>；
- 正版验证不可用时，可用备份密码离线进入，验证通过后通过原版 transfer 切换到正版存档；
- 未登录玩家不会进入世界，也不会出现在 Tab/在线列表；
- 客户端不需要安装任何模组。
```

### 4.2 给正版玩家的说明

```
如果你是正版玩家：
1. 正常正版登录即可进入；
2. 建议进服后执行 /register <密码> <确认密码> 设置离线备份密码；
3. 正版验证不可用/你自己用离线启动时，连接后在登录对话框输入该密码；
4. 备份密码验证通过后会清掉 dialog 并 transfer 回同一服务端，登录阶段切换为正版 UUID，直接进入正版存档；
   如果正版同名在线，备份密码登录会被拒绝并提示等待，不会踢掉对方。
```

### 4.3 给离线玩家的说明

```
离线玩家连接后：
- 第一次：在对话框里输入两次密码完成注册；
- 之后：在对话框里输入密码登录；
- 修改密码：进服后执行 /changepassword <旧密码> <新密码>；
- 登录完成前不会进入世界，超时会按服务器配置断开。
```

### 4.4 数据/安全说明

```
- 正版名字只允许正版登录；离线冒用会被拒绝；
- 正版玩家设置备份密码后，才允许离线用该名字登录；
- 备份密码是真实凭据，请使用强密码，不要与其他账号共用；
- 密码在登录对话框输入，不经过聊天栏，也不会进入命令日志；
- 未完成登录的连接仍会出现在服务器日志/连接列表中，但不在玩家列表和世界里。
```

## 5. 配置语义（给服主）

| 配置 | 说明 |
|---|---|
| `online-mode=true` | 混合登录前提 |
| `premiumBypass=true` | 正版玩家直接进入，不需要密码 |
| `premiumPasswordBackup=true` | 允许正版玩家 /register 设置离线备份密码 |
| `transferEnabled=true` | 备份密码通过后用原版 transfer 切换到正版 UUID/存档 |
| `transferHost` / `transferPort` | transfer 目标；空/0 = 客户端连接时的 host / 服务器端口 |
| `accepts-transfers=true` | server.properties 必须开启，否则原版拒绝 TRANSFER 连接 |
| `premiumNameProtection=true` | 已记录正版名禁止离线冒用；没有备份密码时离线直接拒绝 |
| `fallbackToOfflineWhenAuthServerDown=true` | 会话服务器不可用时是否按离线放行 |
| `skipClientAuthForOfflineClients=true` | 对离线 profileId 跳过客户端 joinServer，避免“无效会话” |
| `forceDisableSecureProfile=true` | 强制有效 enforce-secure-profile=false，避免离线聊天被踢 |
| `requireRegistration=true` | 离线玩家必须先注册 |
| `loginTimeoutSeconds` / `kickOnTimeout` | 对话框超时秒数 / 超时是否踢出（false = 继续等待） |
| `maxLoginAttempts` / `ipBanSeconds` | 密码错误几次封 IP / 封多久 |
| `language` | zh_cn / en_us |
| `offlineSkinsEnabled` / `offlineSkinProvider` | 离线皮肤开关/来源 |
| `offlineSkinSiteRoot` | LittleSkin 等 CustomSkinAPI 根地址 |
| `offlineSkinMineSkinSigning` / `offlineSkinMineSkinApiKey` | MineSkin 签名/Key |
| `offlineSkinAllowUnsignedFallback` | 是否允许未签名皮肤（通常只有本机可见） |

## 6. English Copy (short)

```
PLogin — hybrid authentication for Minecraft 26.2 Fabric.

Premium players join directly and keep their UUID, skin and cape.
Offline players get a vanilla configuration-phase dialog: register on first join,
then enter their password on later joins, before the world is loaded.
Premium players may set an offline backup password with /register and use it
when premium authentication is unavailable.
A successful backup login clears the dialog and sends the vanilla transfer packet
back to the same server with a one-time cookie; the login phase then switches to the
premium UUID and save. This requires accepts-transfers=true in server.properties.
If a premium account with the same name is online, the backup login is rejected until it leaves.
Unauthenticated connections never enter the world, the tab list, or the player list.

No client mod is required.
```
